AI 도구와 활용 원칙

제작 전 과정 — 기획·개발·QA·문서화 — 을 단일 AI 코딩 에이전트 Claude Code로 수행했다. 별도의 이미지·오디오·코드 생성 도구는 쓰지 않았고, 게임 안에는 어떤 AI/LLM도 넣지 않았다(무API·오프라인 원칙). AI는 오롯이 제작 도구다.

«기획을 거의 완벽히 확정 → 개발 → 버그 검증 → 밸런싱은 수치만. 문서가 길어져도 좋으니 충돌·모순이 없는 게 정말 중요하다.»
— 디렉터가 세운 지배 원칙. AI 활용은 이 원칙을 따라 게임 기획 · 게임 개발 · QA 세 국면으로 나뉜다.

세 국면을 관통하는 두 개의 시그니처가 있다. ① 멀티에이전트 워크플로 — 콘셉트 탐색, 구현 gap-map, 적대적 자기검증, 5전략 봇 토너먼트가 모두 여러 에이전트의 병렬·심사 구조로 돌아갔다. ② 근거주의 — 값이 없으면 지어내지 말고 __AMBIGUOUS__로 신고, 아직 안 잰 지표는 null로, «통과»는 커밋 메시지가 아니라 원본 재검증으로. 실제로 이 문서 자체가 그 근거주의의 산물이다 — 약 1,100행 개발 로그(log.md)에서 디렉터의 실제 프롬프트를 추출하고, 모든 인용을 원본과 대조 검증해 작성했다.

게임 기획

Game Design · 무엇을 만들 것인가

활용 내역 — AI가 한 일

무엇을 만들지가 백지인 상태에서, AI가 디렉터와 함께 콘셉트를 수렴시키고 확정 설계를 «기계가 판정하는» 형태로 동결했다.

  • 멀티에이전트 콘셉트 탐색 — 5각도로 후보를 병렬 생성 → 심사 에이전트가 4기준(AI차별성·데모재미·구현가능성·독창성)으로 채점·랭킹해 Top6로 수렴. 이어 3 플레이어 프로파일 × 12 후보로 survivor-like 방향을 도출.
  • 취향 프로파일 증류 — AI가 디렉터의 취향을 한 줄 프로파일(«1시간 미만·반사신경 관대·성장 후 양학»)로 정리, 이후 모든 설계 판단의 기준선으로 삼음.
  • «도려내기»를 설계로 번역 — 강제 공진화(ANTIGEN) 폐기 → 포켓몬식 4타입 상성, 순수 랜덤성의 운빨은 테마 스테이지로 완화, 뱀서의 아이템 노가다는 바운드 아레나 + 자동 수집으로 제거.
  • 디렉터의 메커니즘을 정본화 — 디렉터가 발명한 «속성 스탠스»(투자 레벨만큼만 imbue)·배속 난이도 등을 AI가 평가·채택해 규칙으로 형식화. 콘텐츠는 빌드타임 생성기가 아니라 AI가 설계 에이전트로 직접 저작.
  • «기획을 기계가 판정» — 산문 리뷰 3~4라운드(~7시간)가 같은 클래스 결함으로 비수렴 → 정본을 data/*.json 9종 + check.mjs로 전사. 전사가 산문이 못 잡은 33결함을 적발(같은 탄이 150/140/120으로 갈라져 발사되던 bullets.speed↔emitters.speed 등). node check.mjs → exit 0 = «AI가 아니라 기계가 기획 완료를 판정».
  • 플레이 후 정본 개정 루프 — 진화 재설계·난이도 오버홀·경제 폐지(원데스)·후반 보스 전략화를 정본 개정으로 반영. 디렉터 실플레이(5스테이지 도달)가 «게임 경제는 멀쩡, 봇이 잘못된 계측기»를 확증해 방향을 대전환.

프롬프트 유형 — 디렉터가 준 지시

유형취향·재미 정의
무엇을 만들지 정하기 전에, 자기가 어떤 게임을 왜 좋아하는지·어떤 재미를 원하는지 먼저 규정하고 AI가 그 기준에 맞춰 설계하게 함.
  • 내가 어떤 게임을 왜 좋아하는지 먼저 정확히 파악한 뒤 추천해 달라 — 호흡 긴 게임은 싫고 한 판은 1시간 미만, 최근엔 칼바람·194X·뱀서, 바둑·체스식 전략과 리듬·반응은 싫다, RPG의 성장→양학이 좋다.
  • 단순 양학보다 내 올바른 선택으로 결과가 뚜렷하게 보이는 양학이 좋다. 보스에 약간의 패턴, 탄막을 어느 정도 보고 피하는 수준 — 단 리듬·트위치 반응은 싫다.
  • 쉽게 양학하면 아무도 안 한다. 총알 막기는 너무 수동적이니 내가 능동적으로 공격하는 게 더 좋다.
유형콘셉트 취사선택·방향 전환
AI가 멀티에이전트로 낸 후보·훅 메뉴에서 싫은 요소는 도려내고 좋아하는 요소만 취해 재조합하도록 결정을 내림.
  • 강제 카운터(ANTIGEN)는 두더지잡기 같아 별로다. 차라리 운빨 로그라이크가 낫다 — 단 «특정 공격에 강한 적»은 좋으니 포켓몬 타입 상성으로 가자.
  • 보스를 잡으면 그 패턴을 무조건 얻는 건 별로다 — 뱀서처럼 레벨업 때 무기를 선택하고 싶다. 런앤건은 리소스가 무거우니 제외하자.
  • 전기는 애매하니 물·불·풀·노말 4종으로. 무기는 뱀서식 진화 — 초반엔 약해도 맥스까지 키우면 폭발하는, 참고 키운 보상.
유형설계 원칙·제약 못박기
개별 기능이 아니라 전 설계를 관통하는 원칙·제약(무엇을 넣지 말 것인가)을 선언해 이후 판단의 경계로 삼음.
  • AI는 기획·디자인·개발·디버깅에만 쓰고, 게임 자체는 웹에서 저용량·안정적으로 — 인게임 AI로 API를 쓰면 리소스가 크다.
  • 뱀서에서 귀찮았던 건 맵 저 멀리 아이템 주우러 가는 노가다다. 먹는 타이밍 스킬은 원하지만 노가다는 빼라.
  • 무기·속성 레벨을 코인으로 사는 건 반대다 — 레벨업의 영역을 침범하면 안 된다.
유형디렉터의 메커니즘 발명
메뉴에서 고르는 데 그치지 않고, 직접 구체 메커니즘을 발명·제안하고 AI에게 평가·형식화를 맡김.
  • 무기는 고정하고 속성만 바꾸자 — 속성별 투자 레벨(불+2/물+1/풀+0)을 쌓고, 스탠스를 바꾸면 투자한 만큼의 무기만 그 속성으로 발사, 나머진 무속성. 방향키 + QWER 양손 플레이로.
  • 순수 로그라이크면 운빨겜 같으니 테마 스테이지로 완화하자 — 바다=물 위주 + 풀·노말 소량, 보스는 엔진=불·날개=물처럼 부위별 복합 타입으로.
  • 배속 난이도 — 3배속이면 적·내 공격이 모두 3배·보스 제한 1분, 점수에 반영하면 스피드런 느낌.
유형정합성·정본 확정 요구
기획을 모순 없이 완벽히 확정한 뒤 개발로 넘기려는 요구, 그리고 토대가 충분히 고려됐는지 완결성을 점검하게 함.
  • 기획을 거의 완벽히 확정한 뒤 개발하고, 버그를 검증하고, 밸런싱은 수치만 조절하고 싶다. 문서가 길어져도 좋으니 충돌·모순이 없는 게 정말 중요하다.
  • 게임의 토대는 194X + 로그라이크 + 뱀서 + 상성으로 이해했다. 194X의 적·공격 패턴이 충분히 고려됐나?
유형플레이 후 설계 개정
실제로 플레이한 뒤 «게임이 무엇이어야 하는가»를 바꾸는 정본 개정 요구 — 메커니즘 재설계·난이도 철학·구조 폐지까지.
  • 너무 쉽게 깼다. 6스테이지는 풀속성에 2.5배 패시브, 최종 진화 Top4까지 갖춰야 깰 수 있게 — 더 어렵게 만들어라.
  • 경제를 완전히 제거하자 — 컨티뉴도 없애 원데스로, 소비아이템(폭탄·시간토큰·리롤·실드)도 전부 제거.
  • 보스에 재밌는 트릭을 네가 고민해서 넣어라 — 예를 들어 화산 보스는 물 모듈을 부숴야 불 모듈이 열리는 식으로.

게임 개발

Game Development · 어떻게 만들 것인가

활용 내역 — AI가 한 일

확정된 정본을 바닐라 JS로 «구현»하는 국면. 디렉터가 구현을 통째로 위임했기에, AI가 4층 결정론 아키텍처로 게임을 지어 올렸다.

  • 4층 결정론 아키텍처 — 순수 결정론적 코어(rng 8스트림·프레임당 alloc 0·speed 모르는 고정 dt) / render / data(JSON 9종) / tools. 시뮬이 step.js를 그대로 import → «인증한 것 = 출시되는 것»이 구조적으로 성립.
  • 무의존·무에셋 완주 — 프레임워크·라이브러리 0, 외부 에셋 0. 오디오조차 음원 파일 없이 WebAudio로 절차적 합성(오리지널 칩튠 A단조 BGM + 히트·처치·발악 SFX)해 저작권 음원을 회피.
  • «개발 중 설계 결정 0» — 코드에서 만난 정본 공백을 지어내지 않고 전량 보고: D1 도→라디안 상수(180이 리터럴 화이트리스트 밖 → angle.js로 분리), D2 탄 소멸 훅 부재, D3 killEnemy 미export(무기 6종이 적을 못 죽임).
  • 콘텐츠 데이터 주도 저작 — 무기 거동 패밀리·적 17종·복합 다부위 보스 10종(부위별 속성·봉인 레이어·페이즈3 «발악» 타입 전환)·중간보스 3종·새떼 위기·6 테마 스테이지. 불변식을 지키려 새 엔티티 풀 0(기존 풀 재사용).
  • 이야기처럼 읽히는 133 커밋 — 각 커밋이 check exit 0 · 테스트 통과 · 헤드리스 실증(무크래시·무NaN·결정성) · 브라우저 콘솔 0을 통과해야 다음으로 넘어가는 점진 개발.
왜 개발 프롬프트는 «위임»이 대부분인가. 디렉터는 구현을 통째로 AI에게 맡기고, 자신의 프롬프트를 기획(취향)과 QA(회의적 검증)에 집중시켰다. 그래서 이 국면의 프롬프트는 세부 지시가 아니라 «최종본만 플레이하겠다» 류의 자율 위임과 GO 사인이 특징이다.

프롬프트 유형 — 디렉터가 준 지시

유형자율 완성·일괄 위임
최종본만 플레이하겠다며 로드맵대로 끝까지, 또는 쌓인 계획을 한 번에 다 스스로 완성하라 위임.
  • 난 네가 만든 최종 게임을 플레이할 거야. 네 계획에 맞게 게임을 완성하면 돼.
  • 지금까지 천천히 계획한 걸 다 반영해줘.
  • 키 통일하고, 후반 보스를 다방면으로 전략화해서 — 다 만들고 나서 내가 테스트할게.
유형단계별·에러 없는 진행
계획을 정한 순서대로 밟되 각 스텝을 디버깅·검증하며 결함 없이 넘어가라.
  • A부터 D까지 계획대로 쭉 가되, 각 스텝을 디버깅하며 에러 없이.
  • 네 우선순위대로 쭉 진행해.
유형판단 위임
무엇을 먼저·어떻게 구현할지의 결정을 AI에게 넘김.
  • 지금 상황에서 가장 맞는 판단을 내려서 진행해 달라.
유형착수·전진 GO 사인
확인을 마치고 다음 단계로 넘어가라는 짧은 승인·전진 신호.
  • 시작하자.
  • 상성 잘 반영됐어. 다음으로 진행하자.
  • 지금으로 충분하다. 그대로 가자.

QA

Testing · Balancing · Verification · 올바르고 재밌는가

활용 내역 — AI가 한 일

게임이 «올바르고 재밌는가»를 기계와 사람 양쪽으로 판정했다. AI가 검증 체제를 세우고, 디렉터의 플레이 체감 피드백을 «진단 → 반영 → 재검증» 루프로 소화했다.

  • 40 정적 게이트 + 공허통과 감시 — check.mjs가 정본↔데이터 정합을 매번 재계산. 참조 45곳이 undefined→[]→0행 순회로 «아무것도 안 보고 초록불»을 냈던 사건 이후, 모든 게이트에 «0행 = 위반»을 부착.
  • 373 단위 테스트 + 뮤테이션 테스트 — 일부러 버그를 심어(상성 배율 반전 → 14건 FAIL) «테스트가 통과»가 아니라 «테스트가 버그를 잡는다»를 실증. 원칙: 버그를 잡으면 코드를 고친다, 테스트를 약화하지 않는다.
  • 결정성 회귀 + 자기플레이 밸런싱 — 동일 시드 1800틱 롤링해시 비트 동일. 헤드리스 시뮬(sim.mjs)이 봇으로 수천 판을 돌려 22지표를 채점(안 잰 지표는 null로 통과 위장 금지).
  • 계측이 밝힌 «죽은 구현» — 시뮬 첫 계측이 밸런스가 아니라 구현 결함을 규명: xpScale·spawnDensityScale가 코드에 미적용(후반 스테이지가 의도의 1/6 XP), XP 예산이 여섯 스테이지 «전부» ×4.9로 균일하게 어긋남(스칼라 하나가 빠진 흔적).
  • 1000+판 스트레스 + 멀티에이전트 코드리뷰 — 필멸 1200런 + 무적 딥 80런 + 결정성 120쌍(무크래시·무NaN) 위에, 각 지적을 독립 검증자가 반증 → 27건 중 20건 수정.
  • ★ «봇이 밝힌 것, 사람이 밝힌 것» — 봇 5전략 병렬 워크트리 토너먼트가 병목을 «게임 경제»로 4/5 합의했으나, 디렉터가 직접 5스테이지 도달·최종 진화 완성 → «게임은 멀쩡, 봇이 잘못된 계측기» 확증 → AI(하한 계측) + 사람(실플레이) 상보 계측으로 재편. 적대적 자기검증은 «후반 전면 엘리트화»가 런타임이 읽지 않는 죽은 값이라 실질 무효였음과 보스 발악 22부위 중 6개 미전환을 스스로 적발.

프롬프트 유형 — 디렉터가 준 지시

유형철저 검수·버그 색출 선제 지시
코드를 정독/모듈 단위로 훑어 결함을 미리 전멸하고, 대량 시뮬로 스트레스해 버그·밸런스를 확인하라는 능동적 QA 지시.
  • 코드 결함 해결부터 먼저 하자. 지금 잡을 수 있는 코드 에러를 최대한 다 잡고 넘어가야 나중에 덜 힘들다.
  • 모듈 하나하나 꼼꼼히 검수하고 넘어가야 규모 있는 서비스를 안정 배포할 수 있다. 버그를 최대한 찾자.
  • 코드를 정독해 버그를 고치고, 1000판 넘게 돌려 버그·밸런스를 확인한 뒤 수정 계획을 제안해 달라.
유형플레이 체감 — 가독성·감각의 공백
직접 플레이하며 «의도가 화면·손에 안 읽힌다»를 지목 — 밸런스가 아니라 피드백·가독성의 문제를 짚음.
  • 적이 나에게 공격을 안 해서 긴박감이 없다.
  • 상성을 바꿔야 할 필요성이 안 느껴지고, 어느 적이 어느 속성인지 감이 안 잡힌다.
  • 상성(×2)은 잘 보이는데 역상성(×0.5)은 인식이 어렵다.
유형플레이 체감 — 난이도·긴박감
클리어 난이도의 «맛»을 조정하라 — 너무 쉽다/어렵다, 위기가 끊긴다, 더 긴박했으면 하는 방향 피드백.
  • 너무 쉽게 깼다 — 6스테이지 중 4개를 무피격으로 클리어했다.
  • 스테이지 갈수록 잡몹이 강해지나? 어려우면 차라리 후반은 다 엘리트로 해라.
  • 위기가 진짜 끊임없이 몰려오는 느낌이었으면 한다 — 지금은 위기 흐름이 중간에 끊긴다.
유형밸런싱·계측 지시
밸런스 레버를 «수치만» 돌리거나, 계측기(봇·시뮬)를 더 갈아 측정 가능하게 만들라는 지시.
  • 6스테이지 중 한 스테이지는 쑥쑥 레벨업하며 깨는 맛이 있게, 레벨업을 초반에 특히 싸게 해 달라.
  • 봇 AI에 대규모로 투자해서 계속 밀어붙여라.
  • 봇을 재설계한 뒤에 속성 게이트를 강화하자.
유형반영·정합성 재검증 요구
«정말 다 반영됐나 / 계산이 맞나»를 회의적으로 되물어 재검증을 강제 — 커밋 메시지만 믿지 말라는 압박.
  • 다 반영된 거 맞나? 이제 플레이만 하면 되나?
  • 데미지는 맞게 계산되고 있는 거지?
  • esc로 일시정지가 안 되는 것 같은데? 나머지는 다 만들어졌는지 확인해 달라.
